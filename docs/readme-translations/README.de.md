# Vorlagenpakete für LaTeX, Typst und Markdown

**Deutsch** | [English](../../README.md) | [Español](README.es.md) | [Français](README.fr.md) | [日本語](README.ja.md) | [한국어](README.ko.md) | [Português](README.pt.md) | [Русский](README.ru.md) | [中文](README.zh.md) | [العربية](README.ar.md)

Verbring weniger Zeit mit dem Seitenlayout. Such dir einen Ausgangspunkt für dein nächstes
Paper, deine Abschlussarbeit, deinen Lebenslauf, Vortrag, dein Poster oder deinen Bericht und mach etwas Eigenes daraus.

Diese Sammlung enthält offen lizenzierte Vorlagenpakete, die du mit deinem eigenen
Editor und Compiler nutzen kannst. Die Quellen sind normale Dateien im Format `.tex`, `.typ`
und `.md`. Oleafly ist optional.

**[Galerie ansehen](https://oleafly.com/templates/) ·
[Engine auswählen](#vorlagenverzeichnis) ·
[Sammlung herunterladen](https://github.com/Oleafly/template-packs/archive/refs/heads/main.zip)**

Ein Layout gefunden, das du behalten willst? [Gib dieser Sammlung einen Stern](https://github.com/Oleafly/template-packs),
damit du sie wiederfindest und anderen Schreibenden den Einstieg erleichterst.

## Neue Startvorlagen

- **Markdown:** ein [Forschungs-Kurzbericht](../../packs/markdown-starters/markdown-research-brief/),
  eine [Literaturübersicht](../../packs/markdown-starters/markdown-literature-review/) und
  ein [technischer Bericht](../../packs/markdown-starters/markdown-technical-report/).
- **Typst:** ein [Bericht zur Datenanalyse](../../packs/reports-lab/typst-data-analysis-report/)
  und ein [A3-Forschungsposter](../../packs/slides-posters/typst-research-poster/), beide nur mit eingebauten Typst-Funktionen.
- **LaTeX:** ein [Antwortschreiben an die Gutachtenden](../../packs/academic-writing/response-to-reviewers/)
  mit Kommentaren, Antworten und Angaben zu den überarbeiteten Stellen.

Diese sechs Startvorlagen haben wir selbst geschrieben. Sie enthalten gerenderte Vorschauen und stehen unter CC0-1.0.
Beispieldaten und Beispielkorrespondenz sind als solche gekennzeichnet, damit du sie durch deine eigene Arbeit ersetzen kannst.

## Eine Vorlage verwenden

Wähle eine Vorlage und nimm immer ihren ganzen Ordner mit. Zu den Begleitdateien
können eine Bibliografie, Bilder, Stildateien oder weitere Dokumentabschnitte gehören.
Schau in `template.json` und, falls vorhanden, in `SOURCE.json` nach dem vorgesehenen Compiler,
den Abhängigkeiten, den Hinweisen aus dem Originalprojekt und der Lizenz.

So holst du dir die Sammlung:

```sh
git clone --depth 1 https://github.com/Oleafly/template-packs.git
```

Öffne einen Vorlagenordner in deinem Editor. Mit diesen Befehlen kompilierst du die neuen
Startvorlagen. Führe sie im jeweiligen Vorlagenordner aus:

| Format | PDF erstellen |
| --- | --- |
| LaTeX | `tectonic main.tex` |
| Typst | `typst compile main.typ main.pdf` |
| Markdown | `pandoc main.md --standalone --citeproc --pdf-engine=tectonic -o main.pdf` |

Markdown lässt sich mit `pandoc main.md -o main.docx` auch in ein Word-Dokument umwandeln
und mit `pandoc main.md --standalone -o main.html` in HTML.
Exportoptionen findest du im [Pandoc-Handbuch](https://pandoc.org/MANUAL.html). Falls du zum ersten Mal mit `.typ`-Dateien arbeitest,
hilft dir das [Typst-Tutorial](https://typst.app/docs/tutorial/) weiter.

Die Community-Importe decken viele Versionen und Stile ab. Manche brauchen eine bestimmte
TeX-Engine, installierte Schriften oder Pakete aus einer externen Paketquelle. Ein Eintrag
im Verzeichnis heißt nicht, dass die Vorlage mit jeder Toolchain kompiliert wurde.

## Schreiben und Vorschau an einem Ort?

[Oleafly](https://oleafly.com) ist ein kostenloser Desktop-Arbeitsbereich für LaTeX, Typst
und Markdown. Stöbere in Vorlagen, bearbeite den Quelltext und hab das kompilierte PDF
direkt neben deinem Entwurf im Blick. Füge Zitate hinzu, erstelle Abbildungen oder arbeite mit einem KI-Agenten
am Projekt. Deine Dateien bleiben auf deinem Computer.

Die App kann diese Pakete bei Bedarf herunterladen. Du kannst auch ein bestehendes
Projekt in Oleafly importieren, wenn du dort weiterschreiben möchtest.

**[Oleafly herunterladen](https://github.com/Oleafly/Oleafly/releases/latest) ·
[Dokumentation lesen](https://oleafly.com/docs/) ·
[README der App ansehen](https://github.com/Oleafly/Oleafly#readme)**

## So ist die Sammlung aufgebaut

- `packs/<pack>/<template>/` enthält die Quelldateien und die Manifestdatei `template.json`.
- `catalog.json` listet die herunterladbaren Pakete und ihre Dateien auf. Mit `node gen-catalog.mjs` erzeugst du die Datei neu.
- `docs/templates-*.md` enthält die vollständigen Verzeichnisse pro Engine. Führe `node tools/build-template-index.mjs` aus, um sie und die Tabellen im README zu aktualisieren.
- Die `open-*`-Pakete enthalten importierte Community-Vorlagen und Paketbeispiele. Unsere eigenen Startvorlagen liegen in den übrigen Paketen.
- `tools/website-template-ids.json` hält fest, welche Galerieseiten veröffentlicht sind. Mit `node tools/build-template-index.mjs --refresh-gallery` aktualisierst du die Datei aus der Sitemap der Website.

## Eine Vorlage beitragen, die jemand braucht

Du hast ein Layout für dein Fachgebiet, einen übersichtlicheren Bericht oder eine bessere Grundlage
für einen Vortrag? [Öffne einen Pull Request](https://github.com/Oleafly/template-packs/pulls).
Lies den [Leitfaden zum Erstellen von Vorlagen](../../tools/AUTHORING.md), gib die Lizenz und jede nötige
Namensnennung an und kompiliere die Vorlage, bevor du sie teilst.

So erzeugst du eine Vorschau:

```sh
node tools/build-previews.mjs packs/<pack>/<template>
```

Das Vorschauwerkzeug braucht `pdftoppm` und den passenden Compiler. Markdown-Vorschauen
nutzen Pandoc und Tectonic. Erzeuge danach den Katalog und die Vorlagenverzeichnisse neu.

[Melde eine defekte Vorlage](https://github.com/Oleafly/template-packs/issues)
mit dem Ordnernamen, deiner Compiler-Version und der Fehlermeldung, die du gesehen hast. Eine kleine
Korrektur kann der nächsten Person einen Nachmittag ersparen.

## Lizenzen und Namensnennung

Oleaflys eigene Vorlagen stehen unter **CC0-1.0**. Importierte Vorlagen behalten
die Lizenzen ihrer Originalquelle. Prüfe jedes Manifest, `SOURCE.json` und mitgelieferte
Lizenzdateien, bevor du sie weiterverwendest oder weiterverbreitest. Es gibt keine Gesamtlizenz,
die diese einzelnen Bedingungen ersetzt.

Externe Pakete und Schriften haben eigene Lizenzen. Wenn eine Vorlage nach einer Zeitschrift,
Konferenz, Institution oder einem bekannten Design benannt ist, bedeutet das keine Unterstützung durch die Namensgeber. Prüfe
vor der endgültigen Einreichung die aktuellen offiziellen Vorgaben.

Manche importierten Vorlagen kamen ganz ohne Lizenz. In ihren Manifesten steht
„Unlicensed (no license stated)“ (keine Lizenz angegeben), und `SOURCE.json` verweist auf die Herkunft der
Vorlage. Wenn eine davon von dir stammt und du sie entfernt haben möchtest,
[eröffne ein Issue](https://github.com/Oleafly/template-packs/issues) mit dem
Ordnernamen, und wir nehmen sie ohne Rückfragen heraus.
