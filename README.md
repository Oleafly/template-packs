# LaTeX, Typst & Markdown template packs

Spend less time setting up the page. Find a starting point for your next
paper, thesis, CV, talk, poster, or report, then make it yours.

This is a collection of openly licensed template packs you can use with your
own editor and compiler. The sources are ordinary `.tex`, `.typ`, and `.md`
files. Oleafly is optional.

**[Browse the gallery](https://oleafly.com/templates/) ·
[Choose an engine](#template-index) ·
[Download the collection](https://github.com/Oleafly/template-packs/archive/refs/heads/main.zip)**

Found a layout you want to keep? [Give this collection a star](https://github.com/Oleafly/template-packs)
so you can find it again and help another writer get started.

## New starting points

- **Markdown:** a [research brief](packs/markdown-starters/markdown-research-brief/),
  [literature review](packs/markdown-starters/markdown-literature-review/), and
  [technical report](packs/markdown-starters/markdown-technical-report/).
- **Typst:** a [data analysis report](packs/reports-lab/typst-data-analysis-report/)
  and an [A3 research poster](packs/slides-posters/typst-research-poster/), using built-in Typst features.
- **LaTeX:** a [response-to-reviewers letter](packs/academic-writing/response-to-reviewers/)
  with comments, replies, and revision locations.

These six original starters include rendered previews and use CC0-1.0.
Example data and correspondence are labeled so you can replace them with your own work.

## Use a template

Choose a template and keep its complete folder together. Supporting files
can include a bibliography, images, styles, or additional document sections.
Check `template.json` and any `SOURCE.json` for the intended compiler,
dependencies, upstream instructions, and license.

To get the collection:

```sh
git clone --depth 1 https://github.com/Oleafly/template-packs.git
```

Open a template folder in your editor. These commands build the new starters
from inside their respective folders:

| Format | Build a PDF |
| --- | --- |
| LaTeX | `tectonic main.tex` |
| Typst | `typst compile main.typ main.pdf` |
| Markdown | `pandoc main.md --standalone --citeproc --pdf-engine=tectonic -o main.pdf` |

Markdown can also become a Word document with `pandoc main.md -o main.docx`,
or HTML with `pandoc main.md --standalone -o main.html`.
See the [Pandoc guide](https://pandoc.org/MANUAL.html) for export options and
[Typst's tutorial](https://typst.app/docs/tutorial/) if you are new to `.typ` files.

Community imports cover many versions and styles. Some require a particular
TeX engine, installed fonts, or packages from an upstream registry. An entry
in the index does not mean it has been compiled with every toolchain.

## Want to write and preview in one place?

[Oleafly](https://oleafly.com) is a free desktop workspace for LaTeX, Typst,
and Markdown. Browse templates, edit the source, and keep the compiled PDF
beside your draft. Add citations, create figures, or work with an AI agent
on the project. Your files stay on your computer.

The app can fetch these packs on demand. You can also bring an existing
project into Oleafly when you want to continue writing there.

**[Download Oleafly](https://github.com/Oleafly/Oleafly/releases/latest) ·
[Read the docs](https://oleafly.com/docs/) ·
[Explore the app README](https://github.com/Oleafly/Oleafly#readme)**

## How the collection is organized

- `packs/<pack>/<template>/` contains the source files and a `template.json` manifest.
- `catalog.json` lists downloadable packs and their files. Regenerate it with `node gen-catalog.mjs`.
- `docs/templates-*.md` contains the complete engine indexes. Run `node tools/build-template-index.mjs` to refresh them and the README tables.
- `open-*` packs contain imported community templates and package examples. Original starters live in the other packs.
- `tools/website-template-ids.json` records published gallery pages. Refresh it from the website sitemap with `node tools/build-template-index.mjs --refresh-gallery`.

## Add a template someone will use

Have a layout for your field, a clearer report, or a better starting point
for a talk? [Open a pull request](https://github.com/Oleafly/template-packs/pulls).
Read the [authoring guide](tools/AUTHORING.md), include the license and any
required attribution, and compile the template before sharing it.

Generate a preview with:

```sh
node tools/build-previews.mjs packs/<pack>/<template>
```

The preview tool needs `pdftoppm` and the relevant compiler. Markdown previews
use Pandoc and Tectonic. Then regenerate the catalog and template indexes.

[Report a broken template](https://github.com/Oleafly/template-packs/issues)
with its folder name, your compiler version, and the error you saw. A small
fix can save the next person an afternoon.
