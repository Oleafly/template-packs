# 项目管理总览

## 1. 项目定位

本项目是一个面向吉林大学本科毕业论文（设计）的 LaTeX 模板仓库，核心目标是：

- 保证模板格式尽量贴近学校规范。
- 让首次接触 LaTeX 的同学也能快速上手。
- 保持 GitHub 仓库可持续维护、可追踪、可协作。

## 2. 当前项目范围

### 核心文件

- `jluthesis.cls`：模板格式与样式逻辑核心。
- `jluthesis.cfg`：用户信息与模板参数配置。
- `main.tex`：示例论文入口文件。
- `references.bib`：参考文献数据库。
- `README.md`：对外说明文档。

### 资源文件

- `docs/`：学校规范、承诺书、封面等参考资料。
- `fonts/`：模板依赖字体。
- `images/`：示例图片与素材。

### 协作与管理文件

- `CONTRIBUTING.md`：贡献者与维护者入口说明。
- `PROJECT_MANAGEMENT.md`：本项目管理说明。
- `CHANGELOG.md`：持续变更记录。
- `docs/GITHUB_SYNC.md`：GitHub 同步说明。
- `scripts/sync_project_to_github.ps1`：GitHub 同步脚本。
- `.github/`：Issue / PR 模板。

## 3. 任务分层

### P0：模板正确性

- 检查封面、目录、摘要、参考文献等是否符合学校要求。
- 修复编译错误、路径错误、字体错误、编码错误。
- 保证 `main.tex` 在推荐编译链下可以稳定产出 PDF。

### P1：文档与易用性

- 完善 README、常见问题、写作指南。
- 保持示例内容、图片、参考文献可直接运行。
- 让新用户可以在本地和 Overleaf 两端都顺利使用。

### P2：仓库协作与发布

- 统一提交说明与变更记录。
- 使用 GitHub Issues 跟踪模板缺陷和文档任务。
- 在重要节点打 Tag 或发布 Release。

## 4. 里程碑建议

### M1：仓库稳定化

- README、忽略规则、同步流程清晰。
- 远端仓库可正常拉取、提交、推送。
- 没有未解决的冲突和悬挂流程。

### M2：模板可用性增强

- 补齐模板编译说明与 FAQ。
- 增加常见排版调整入口说明。
- 优化示例内容与目录结构说明。

### M3：版本化发布

- 为外部用户提供稳定版本说明。
- 按变更记录整理 Release Notes。
- 在 README 中明确推荐版本和注意事项。

## 5. GitHub 管理方式

推荐直接把 GitHub 用作项目主看板：

- `Bug Report`：记录编译失败、样式错误、字体缺失、路径问题。
- `Documentation Task`：记录 README、FAQ、示例说明更新。
- Pull Request：每次修改说明“改了什么、为什么改、如何验证”。

建议的 Issue 标签：

- `bug`
- `docs`
- `format`
- `enhancement`
- `release`
- `good first issue`

建议的里程碑：

- `v0.1 仓库稳定`
- `v0.2 文档完善`
- `v1.0 首个稳定模板版本`

## 6. 日常维护流程

1. 先运行 `git status`，确认当前工作区状态。
2. 修改模板、文档或资源文件。
3. 用 `git add <文件名>` 显式暂存准备提交的文件。
4. 在 `CHANGELOG.md` 记录本次改动。
5. 使用 `scripts/sync_project_to_github.ps1 -Message "..."` 执行本地提交与同步。
6. 只有在确认所有改动都应一起提交时，才使用 `-StageAll`。
7. 如果出现远端分叉，优先先解决冲突，再继续推送。

## 7. 完成定义

一个任务可以视为完成，至少要满足以下条件：

- 相关文件已经更新。
- README 或说明文档已同步补充。
- `CHANGELOG.md` 已登记变更。
- GitHub 上有对应 Issue 或可追踪的提交记录。

## 8. 风险清单

- 学校格式要求可能临时调整，模板需要跟进。
- 用户本地 TeX 环境差异可能导致“同模板不同结果”。
- 字体与编码问题在 Windows / macOS / Overleaf 之间容易出现差异。
- 远端与本地并行修改 README 或模板核心文件时，最容易出现合并冲突。

- 清理并保持 `main.tex` 示例内容编码一致。
- 为模板建立一次完整编译验证流程。
- 把 GitHub 上的 Issue / PR 使用起来，减少口头式维护。
